# REVIEW.md

Defects found in the starter `app/main.py` (helpers and endpoints).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` / line ~46 | Never pings MongoDB; always returns 200 even if the database is down | Take MongoDB offline → GET /health still returns `{"status":"ok"}` | Added `client.admin.command('ping')`; raise HTTP 503 on any exception |
| 2 | `compute_late_minutes()` / lines ~29-33 | Punch-in is used as naive local time without converting to IST first; threshold is `> 10` (whole minutes) not `> 600` seconds, so 10:40:01 on a 09:30 shift would return 0 instead of 70; no truncation to the second | An employee punching in at 09:40:01 IST on a 09:30 shift gets 0 late minutes from the starter but the correct answer is 70 | Convert punch_in to IST first; compare elapsed seconds `> 600`; use `int(elapsed_secs // 60)` for a floor |
| 3 | `compute_work_hours()` / lines ~36-37 | Uses Python's built-in `round()`, which applies banker's rounding (round-half-to-even); a duration that falls exactly on a 0.5-hour boundary may round the wrong way | 1h 30min → Python `round(1.5, 2)` stays 1.5, but 2h 30min 30sec → `round(2.508..., 2)` may give 2.51 or 2.50 depending on the digit | Replaced with `round_half_up()` using `decimal.Decimal` and `ROUND_HALF_UP` |
| 4 | `compute_overtime()` / lines ~40-43 | No minimum threshold (should be ≥ 30 min / 1800 s before overtime counts); `shift_end_dt` is built from `date_str` without any timezone, then compared to a naive `punch_out`; overnight shifts are not handled (shift_end may be on the next calendar day); negative overtime returned via `max(0, ...)` when punching out early | An employee who stays exactly 29 min past shift end gets non-zero overtime; overnight shift employee gets the wrong shift-end date; result can also silently underflow | Added 1800-second minimum; built `shift_end_dt` correctly for both normal and overnight shifts; kept all datetimes in naive UTC |
| 5 | `create_employee()` / lines ~60-67 | Check-then-insert race condition: two simultaneous requests can both pass the `find_one` check and both succeed; `datetime.now()` stores naive local time, not UTC; response includes raw MongoDB `_id` and does not convert `created_at` to epoch ms | Two concurrent POSTs with the same `emp_code` both return 201 and create two documents; `created_at` has the wrong timezone; API client receives `_id` which is not part of the contract | Rely on the unique index and catch `DuplicateKeyError` → 409; store `datetime.now(timezone.utc).replace(tzinfo=None)` for naive UTC; `serialize_employee()` strips `_id` and converts `created_at` |
| 6 | `list_employees()` / lines ~70-74 | `skip = page * page_size` skips one extra page (off-by-one: page 1 skips 20 records); `total` counts all documents, ignoring the department filter; no sort by `emp_code`; returns raw documents without epoch-ms conversion | Requesting page 1 returns records 21–40; `total` is inflated when a department filter is active; order is non-deterministic | Changed to `(page - 1) * page_size`; count with the same filter query; added `.sort('emp_code', ASCENDING)`; serialize with `serialize_employee()` |
| 7 | `punch_in()` / lines ~77-95 | No 404 guard for unknown employee — code crashes with `AttributeError` on `emp["shift_start"]` when `emp` is `None`; `datetime.fromtimestamp()` without tz produces naive local time; check-then-insert race; response includes `"id"` field (not in contract); no IST date + overnight shift logic; no status validation; no truncation to second | Punch-in for a non-existent emp_code → unhandled 500; wrong attendance date near midnight; duplicate punch-in may succeed under race; response shape does not match OpenAPI spec | Added employee 404 check; convert via `ms_to_dt()` then strip tz; `insert_one` + `DuplicateKeyError` → 409; `attendance_date()` for correct IST/overnight date; status validation; truncate microseconds; `serialize_record()` strips `_id` |
| 8 | `list_attendance()` / lines ~97-111 | `list(db.attendance_logs.find(q))` loads the entire matching collection into Python memory before sorting and paginating; `total = len(docs)` returns only the number of fetched documents (the full set here, wasting RAM); sorting is done in Python; returns `"id"` field and raw datetime objects instead of the contract fields | With 100k records and no filters the server loads all of them into RAM; response shape does not match contract | Use cursor `.sort().skip().limit()`; `count_documents(q)` for the real total; `serialize_record()` for correct output shape |

---

## Not a defect

- The `PunchInIn` model accepts any integer for `punched_at` without range-checking. This is a missing feature (no validation), not a defect of the code that is already there.
- The starter omits `POST /attendance/punch-out`, `PATCH /attendance/{emp_code}/{date}`, and all analytics/admin endpoints entirely. These are unimplemented features, not bugs in existing code.
